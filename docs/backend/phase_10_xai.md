# OraVisionAI — Phase 10: Explainable AI (XAI) Architecture

## 1. Overview & Architecture

Phase 10 integrates the **Explainable AI (XAI) Subsystem** for the OraVisionAI backend. Operating as a post-inference diagnostic explanation layer, the subsystem explains predictions generated by the **7-class EfficientNetB0 oral lesion classifier** without altering the underlying clinical predictions.

```
Patient Screening Image (PostgreSQL screening_images)
                 │
                 ▼
StorageService (Download from Firebase Storage / Local cache)
                 │
                 ▼
Image Preprocessing Pipeline (224×224×3, RGB float32, EfficientNet Normalization)
                 │
                 ▼
AI Prediction & Target Class Resolution (Predicted Index 0..6)
                 │
       ┌─────────┴───────────────────────────────────────────┐
       │                                                     │
       ▼                                                     ▼
PRIMARY METHODS (User-Facing = True)         SECONDARY METHODS (User-Facing = False)
 ├── Occlusion Sensitivity                     ├── Grad-CAM++
 └── Grad-CAM                                  ├── LayerCAM
                                               ├── Score-CAM
                                               └── Integrated Gradients
       │                                                     │
       └─────────────────────────┬───────────────────────────┘
                                 │
                                 ▼
Heatmap Normalization ([0.0, 1.0] Range, NaN/Inf Sanitation)
                                 │
                                 ▼
Visualization Rendering (Jet Colormap, Bilinear Resizing, Overlay Blending α=0.45)
                                 │
                                 ▼
Firebase Storage Upload
  ├── Raw Heatmap: xai/{patient_id}/{screening_id}/{prediction_id}/{method}/heatmap_{hash}.png
  └── Blended Overlay: xai/{patient_id}/{screening_id}/{prediction_id}/{method}/overlay_{hash}.png
                                 │
                                 ▼
PostgreSQL Transaction Persistence (`xai_results`)
```

## 2. Method Classification & Taxonomy

The XAI subsystem categorizes methods into **Primary** (displayed by default in the patient/dentist interface) and **Secondary** (on-demand technical deep dives):

| Method | Database Key | Priority | `is_primary_user_facing` | Theoretical Mechanism |
|---|---|---|---|---|
| **Occlusion Sensitivity** | `occlusion_sensitivity` | **PRIMARY** | `True` | Sliding perturbation patch measuring drop in target class confidence |
| **Grad-CAM** | `grad_cam` | **PRIMARY** | `True` | Global-average-pooled gradients weighting final convolutional feature maps with ReLU |
| **Grad-CAM++** | `grad_cam_plus_plus` | **SECONDARY** | `False` | Higher-order positive gradient spatial weighting for fine-grained lesions |
| **LayerCAM** | `layer_cam` | **SECONDARY** | `False` | Element-wise spatial gradient weighting preserving localized lesion boundaries |
| **Score-CAM** | `score_cam` | **SECONDARY** | `False` | Perturbation scoring using top activation channels as mask inputs |
| **Integrated Gradients** | `integrated_gradients` | **SECONDARY** | `False` | Path integral of gradients from a black reference baseline ($x_0 = \mathbf{0}$) |

## 3. Mathematical Formulations & Algorithms

### 3.1 Occlusion Sensitivity
- Target: $S_c = f_c(I)$ where $c \in \{0 \dots 6\}$.
- Sliding patch size: `32 × 32` (configurable via `XAI_OCCLUSION_PATCH_SIZE`).
- Stride: `16` (configurable via `XAI_OCCLUSION_STRIDE`).
- Attribution: $\Delta S_c(i, j) = \max(0.0, S_c(I) - S_c(I_{\text{masked}(i, j)}))$.

### 3.2 Grad-CAM
- Target convolutional layer: Automatically resolved (`block6a_expand_conv` or last 4D Tensor output).
- Gradient pooling: $\alpha_k^c = \frac{1}{Z} \sum_i \sum_j \frac{\partial y_c}{\partial A_{i,j}^k}$.
- Heatmap: $L_{\text{Grad-CAM}}^c = \text{ReLU}\left( \sum_k \alpha_k^c A^k \right)$.

### 3.3 Grad-CAM++
- Weights: $w_k^c = \sum_{i,j} \alpha_{i,j}^{k,c} \text{ReLU}\left(\frac{\partial y_c}{\partial A_{i,j}^k}\right)$.
- Heatmap: $L_{\text{Grad-CAM++}}^c = \text{ReLU}\left( \sum_k w_k^c A^k \right)$.

### 3.4 LayerCAM
- Element-wise spatial weighting: $w_{i,j}^k = \text{ReLU}\left(\frac{\partial y_c}{\partial A_{i,j}^k}\right)$.
- Heatmap: $L_{\text{LayerCAM}}^c = \text{ReLU}\left( \sum_k w_{i,j}^k \cdot A_{i,j}^k \right)$.

### 3.5 Score-CAM
- Top $K$ channels selected by activation variance ($K \le 16$, configurable via `XAI_SCORECAM_TOP_CHANNELS`).
- Mask creation: $M_k = I \odot \text{Upsample}(A^k)$.
- Forward pass score: $s_k = f_c(M_k)$.
- Heatmap: $L_{\text{Score-CAM}}^c = \text{ReLU}\left( \sum_k s_k \cdot A^k \right)$.

### 3.6 Integrated Gradients
- Baseline: $x_0 = \mathbf{0}$.
- Steps: $m = 25$ (configurable via `XAI_IG_STEPS`).
- Approximation: $\text{IG}_i(x) = (x_i - x_{0,i}) \times \frac{1}{m} \sum_{k=1}^m \nabla_x f_c\left(x_0 + \frac{k}{m}(x - x_0)\right)$.
- Attribution map: $H(i, j) = \sum_c |\text{IG}_{i,j,c}(x)|$.

## 4. Heatmap Normalization & Visualization Rendering

1. **Normalization**:
   $$\hat{H} = \frac{H - \min(H)}{\max(H) - \min(H) + \epsilon}$$
   - Any NaN, positive infinity, or negative infinity values are replaced with $0.0$.
   - Constant or all-zero matrices return uniform zero arrays without divide-by-zero errors.
2. **Resizing & Colormapping**:
   - Heatmaps are interpolated to the original oral photograph resolution using bilinear resampling.
   - Standard Jet colormap is applied to produce a 3-channel RGB representation.
   - Overlays are created by alpha blending: $\text{Overlay} = 0.45 \times \text{Heatmap}_{\text{RGB}} + 0.55 \times \text{Original}_{\text{RGB}}$.

## 5. Database Schema & Persistence

Stored in the approved `xai_results` table:
- `id`: UUID (Primary Key)
- `ai_prediction_id`: UUID (Foreign Key `ai_predictions.id` CASCADE)
- `screening_image_id`: UUID (Foreign Key `screening_images.id` CASCADE)
- `method`: String(50) with Check Constraint: `('grad_cam', 'occlusion_sensitivity', 'score_cam', 'grad_cam_plus_plus', 'layer_cam', 'integrated_gradients')`
- `target_layer`: Optional[String(100)] (e.g. `block6a_expand_conv`)
- `is_primary_user_facing`: Boolean (`True` for Occlusion & Grad-CAM, `False` for secondary methods)
- `heatmap_storage_path`: Text (`xai/.../heatmap_{hash}.png`)
- `overlay_image_storage_path`: Text (`xai/.../overlay_{hash}.png`)
- `parameters`: JSONB (capturing latency, resolution, target class, and parameters)
- `created_at`: DateTime(timezone=True)

---

## 6. Caching & Idempotency

- When `POST /api/screenings/{id}/xai` is called with `force_recompute=False` (default):
  - Queries existing `xai_results` for the screening prediction.
  - Reuses and returns previously generated records without recomputing heatmaps or writing duplicate rows to PostgreSQL.
- Passing `force_recompute=True` explicitly recalculates and updates artifacts.

---

## 7. Security, Ownership & Role Enforcement

- **Patient Ownership**: Verified via `Screening.patient_id == current_patient.id`. Cross-patient requests immediately return `404 Not Found`.
- **Role Enforcement**: Protected with `require_patient`. Dentist and Admin users receive `403 Forbidden` on patient self-service XAI routes.
- **Secrets Audit**: Zero hardcoded credentials or server paths across all source files.
